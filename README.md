# РельсЛаб — методичка по симулятору, Python API, блокам и датасету

Статический сайт-стенд «киберфизический железнодорожный полигон»: два кольца пути,
две стрелки, три состава, СЦБ, камера ИИ, лазерный пост и программируемый диспетчер.

Сборка не нужна: откройте `index.html` в браузере (Chrome/Edge/Firefox). Все скрипты
работают локально, интернет требуется только для шрифтов.

---

## 1. Состав проекта

```
index.html          разметка страницы и все панели
js/core.js          утилиты и namespace RL ($, el$, clamp, mmss, svgEl)
js/fx.js            звук, тема, статусы систем
js/pyapi.js         мини-интерпретатор Python-подобного API (без Pyodide)
js/sim.js           движок «Готового макета»: поезда, СЦБ, CV, лазер, датасет, лаборатория
js/builder.js       движок «Конструктора» (своя сетка путей)
styles/tokens.css   дизайн-токены (цвета, радиусы, тени, шрифты)
styles/base.css     каркас страницы, шапка, hero, футер
styles/console.css  сцена, пульт, кнопки, CV/лазер
styles/content.css  контентные секции
styles/responsive.css брейкпоинты
```

Порядок подключения скриптов важен: `core.js → fx.js → pyapi.js → sim.js → builder.js`.

## 2. Быстрый старт

1. Откройте `index.html`.
2. Вкладка **«Готовый макет»** — поезд А под ручным управлением, Б и В автономны.
3. Пульт справа: вкладки **Тяга · Путь · Сенсоры · Журнал**.
4. Лаборатория алгоритмов — блок под сценой: режимы **Python / Блоки**, пресеты
   `01_scb_base`, `02_green_wave`, `03_laser_diag`, `04_eco_drive`, кнопка **Применить**.

Основные элементы управления:

| Элемент | Что делает |
|---|---|
| Скорость (ползунок) | задаёт целевую скорость поезда А в % от максимума |
| Вперёд / Назад | реверс; направление меняется только после полной остановки |
| Длина состава | 1–8 вагонов, сразу влияет на массу, тормозной путь и CV-рамку |
| Стоп / Пауза / Гудок / Сброс | остановка, пауза симуляции, тифон, возврат сцены в исходное состояние |
| Защита от столкновений (ATP) | автоторможение перед занятым/закрытым блоком |
| Стрелка 1 / 2 | ручной перевод; занятую стрелку переключить нельзя |
| Автодиспетчер | автоматический перевод стрелок с интервалом (по умолчанию 6 с) |
| Камера ИИ | включает CV-рамки, подписи классов и детекцию помехи |
| Лазерный пост | измерения на блоке О5 при проходе состава |
| Помеха на пути | ставит/убирает препятствие на свободном блоке |
| Клик по светофору | закрывает/открывает блок на ремонт (рельсовая цепь занята) |

## 3. Python API диспетчера

Скрипт пишется в поле кода лаборатории и запускается кнопкой **Применить**.
Это не CPython: работает компактный интерпретатор из `js/pyapi.js`, поэтому доступно
подмножество синтаксиса, зато всё выполняется мгновенно в браузере.

### 3.1. Точки входа

```python
def on_tick(railway, trains):
    # вызывается 10 раз в секунду (каждые 100 мс)
    ...

def on_wheel_scan(train, flange_wear_mm):
    # вызывается при каждом проходе состава через лазерный пост О5
    # flange_wear_mm — измеренный износ гребня, 0.9…2.2 мм
    ...
```

* Оба обработчика необязательны, но нужен хотя бы один — иначе скрипт ничего не делает.
* Код верхнего уровня выполняется один раз при компиляции:
  `railway.enable_sensor("LASER_GATE_O5")` сработает сразу после «Применить».
* Ошибка компиляции или выполнения выводится в строку статуса и в журнал,
  после чего скрипт останавливается (кнопка «Применить» запускает его заново).
* Лимиты: 60 000 операций на один вызов, глубина рекурсии 24, `while` — не более
  5000 итераций. Это защита от зависания вкладки.

### 3.2. Объект `railway`

| Обращение | Тип | Описание |
|---|---|---|
| `railway.time` | число | модельное время, с |
| `railway.switch_1` | строка | `"straight"` или `"divert"` |
| `railway.switch_2` | строка | `"straight"` или `"divert"` |
| `railway.obstacle` | bool | есть ли помеха на пути |
| `railway.log("текст")` | метод | запись в журнал диспетчера |
| `railway.next_block_occupied(train)` | метод → bool | занят/закрыт блок по ходу состава |
| `railway.auto_dispatcher(interval_sec=6)` | метод | включить автодиспетчер с интервалом 1–30 с |
| `railway.route_others_to_inner(except_train="A")` | метод | увести все составы, кроме указанного, на внутреннее кольцо |
| `railway.set_switch(1, "divert")` | метод | явный перевод стрелки (`"straight"` / `"divert"`) |
| `railway.enable_sensor("LASER_GATE_O5")` | метод | включить лазерный пост |
| `railway.divert_to_depot(train)` | метод | ограничить состав 45% и направить в депо |
| `railway.close_block("O:3")` | метод | закрыть блок на ремонт |
| `railway.open_block("O:3")` | метод | открыть блок |
| `railway.block_closed("O:3")` | метод → bool | закрыт ли блок |

Ключи блоков: `O:0…O:n` — внешнее кольцо, `I:0…I:n` — внутреннее.

### 3.3. Объект поезда

| Обращение | Тип | Описание |
|---|---|---|
| `tr.id` | строка | `"A"`, `"B"`, `"C"` |
| `tr.name` | строка | «Поезд А» и т.д. |
| `tr.speed` | число | текущая скорость, доля от максимума (0…1) |
| `tr.vmax` | число | максимальная скорость состава |
| `tr.length` | число | вагонов в составе |
| `tr.track` | строка | текущее кольцо: `"O"` или `"I"` |
| `tr.block` | строка | ключ текущего блока |
| `tr.waiting` | bool | стоит ли состав перед занятым блоком |
| `tr.auto` | bool | автономный ли состав |
| `tr.distance` | число | пройденный путь, м (модельные) |
| `tr.energy` | число | израсходованная энергия, усл. Вт·ч |
| `tr.brake_smooth()` | метод | плавно затормозить (действует один тик) |
| `tr.set_speed_limit(0.45)` | метод | ограничить скорость долей от максимума |
| `tr.limit_acceleration(0.62)` | метод | ограничить ускорение (0…1) |
| `tr.enable_regenerative_braking(eff=0.75)` | метод | рекуперация: усиливает торможение и возвращает энергию |

Ограничения `set_speed_limit` и `limit_acceleration` сохраняются до следующей
команды или до «Сброса» сцены.

### 3.4. Набор `trains`

```python
for tr in trains:                 # перебор всех составов
    print(tr.id, tr.speed)

express = trains["A"]             # доступ по идентификатору
count = len(trains)
```

### 3.5. Встроенные функции

`len`, `range`, `min`, `max`, `abs`, `round`, `int`, `str`, `print`, константы
`True`, `False`, `None`.

### 3.6. Поддерживаемый синтаксис

`def`, `for … in`, `while`, `if / elif / else`, `return`, `break`, `continue`, `pass`,
присваивание в имя и в атрибут (`tr.speed = 1`), вызовы, индексация, атрибуты,
арифметика `+ - * / // % **`, сравнения, `and / or / not`, `in`.

Не поддерживаются: импорты, классы, словари, списковые включения, f-строки,
`try/except`, срезы. Для учебных сценариев этого достаточно.

### 3.7. Готовые примеры

**Базовая автоблокировка**

```python
def on_tick(railway, trains):
    for tr in trains:
        if railway.next_block_occupied(tr):
            tr.brake_smooth()
    railway.auto_dispatcher(interval_sec=6)
```

**Зелёная волна для экспресса**

```python
def on_tick(railway, trains):
    express = trains["A"]
    if express.track == "O":
        railway.route_others_to_inner(except_train="A")
```

**Дефектоскопия с отводом в депо**

```python
railway.enable_sensor("LASER_GATE_O5")

def on_wheel_scan(train, flange_wear_mm):
    if flange_wear_mm > 1.5:
        train.set_speed_limit(0.45)
        railway.divert_to_depot(train)
```

**Эко-вождение**

```python
def on_tick(railway, trains):
    for tr in trains:
        tr.limit_acceleration(0.62)
        tr.enable_regenerative_braking(eff=0.75)
```

**Свой сценарий: закрыть блок и предупредить**

```python
def on_tick(railway, trains):
    if railway.time > 20 and not railway.block_closed("O:3"):
        railway.close_block("O:3")
        railway.log("Учебный отказ рельсовой цепи на О4")
```

## 4. Блочный конструктор

Переключатель **Python / Блоки** в шапке лаборатории. В режиме «Блоки» выбираются
два выпадающих списка: **КОГДА** (условие) и **ТОГДА** (действие). Любое изменение
сразу генерирует Python-код, компилирует и запускает его — то есть блоки и текстовый
режим работают на одном движке.

Условия задают обработчик и обёртку:

| Условие | Что генерируется |
|---|---|
| блок-участок впереди занят или закрыт | `on_tick` + цикл по составам + `if railway.next_block_occupied(tr)` |
| поезд А движется по внешнему кольцу | `on_tick` + `express = trains["A"]` + `if express.track == "O"` |
| лазерный пост О5 зафиксировал гребень > 1.5 мм | `on_wheel_scan` + `if flange_wear_mm > 1.5` |
| активен энергосберегающий график | `on_tick` без дополнительного условия |

Действия подставляются в тело условия с правильным отступом. Комбинации свободные:
например, «когда лазер > 1.5 мм» → «увести Б, В на внутреннее кольцо».

Сгенерированный код можно переключиться в режим «Python», отредактировать и
применить вручную.

## 5. Датасет и камера ИИ

Камера ИИ рисует рамки составов, подписи класса, число вагонов и скорость.
Распознавание окраса локомотива А работает по модели, которую можно дообучать.

Как это устроено:

1. Модель хранит центроиды окрасок в RGB (`cvModel.classes`).
2. Для текущего окраса вычисляется ближайший центроид и уверенность по расстоянию.
3. Если расстояние больше порога — объект считается неизвестным, в подписи
   появляется `НЕИЗВ_ЛОК · N% [ОБУЧИТЕ CV]`, рамка становится предупреждающей.

Порядок работы:

1. Панель **Сенсоры** → блок «Датасет · окрас локомотива А».
2. Выберите окрас: Штатн. (уже в базе), Экспресс, Маневр., Спец.
3. Для нового окраса нажмите **«Собрать датасет и обучить (24 кадра)»**.
   Прогресс идёт по кадрам, сбор занимает около 5 секунд.
4. После обучения класс добавляется в модель, считается mAP@50 на валидации
   (40 синтетических кадров с шумом сенсора) и обновляются подписи CV.
5. Перекраска в обученный класс сразу распознаётся; перекраска в необученный —
   снова требует дообучения.

Обучение сохраняется на время сессии страницы. «Сброс» сцены модель не стирает.

## 7. Как расширить систему

**Добавить пресет алгоритма.** В `js/sim.js` найдите `const ALGOS = {…}` и добавьте
запись `{name, code}`; кнопку-пилюлю продублируйте в `index.html`
(`<button class="lab-pill" data-algo="ключ">`).

**Добавить метод API.** В `js/sim.js`:

* методы макета — в `pyRailwayApi()`, в объект методов;
* свойства и методы поезда — в `pyTrainApi()`;
* свойства-функции вызываются без аргументов, методы получают `(args, kwargs)`.

**Добавить окрас.** В `LIVERIES` укажите `color` (CSS), `rgb` (для модели),
`clsName`, `trained:false`; кнопку `.swatch-btn` добавьте в `index.html`.

**Поменять поведение СЦБ.** Логика блокировок — `blocked()`, `plan()`, `update()`
в `js/sim.js`. Дискретная логика блоков намеренно отделена от плавной интерполяции
движения (`vpos`, `lerpInto`).

## 8. Диагностика

| Симптом | Причина и решение |
|---|---|
| «Ошибка скрипта: … строка N» | синтаксис или неизвестный метод; проверьте отступы (4 пробела) и имена |
| «Превышен лимит операций» | бесконечный цикл; добавьте условие выхода |
| Скрипт не реагирует | нет `on_tick` / `on_wheel_scan`, либо скрипт остановлен после ошибки — нажмите «Применить» |
| Стрелка не переключается | на стрелке стоит состав; дождитесь освобождения |
| CV-подпись «НЕИЗВ_ЛОК» | окрас не входит в датасет — обучите модель |
| Нет звука | браузер включает аудио после первого клика по странице |
| Изменения не видны | обновите страницу с очисткой кэша (Ctrl+F5) |

## 9. Технические заметки

* Движение поездов интерполируется между точками пути каждый кадр, а логика СЦБ
  остаётся дискретной — так состав движется плавно без «телепортов» на стрелках.
* Геометрия путей один раз раскладывается в таблицы (`mk`, `sample`), поэтому
  `getPointAtLength` не вызывается в горячем цикле.
* Для поиска препятствий используется кэш координат (`buildNearCache`), что убирает
  просадки FPS на длинных составах.
* Камера ИИ обновляет рамки раз в 50 мс (20 Гц), сами поезда остаются плавными.
* Пользовательский скрипт вызывается 10 раз в секунду; ошибки не роняют страницу,
  а останавливают только скрипт.
